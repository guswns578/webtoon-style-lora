# 실험 기록

README의 연구 흐름 ①~⑤ 순서로 정리했습니다. 수치마다 **어느 단계, 어떤 모델에서 나온 값인지**를 밝혔습니다. 앞 단계의 수치를 현재 Studio 모델의 성능으로 옮겨 쓰지 않습니다.

공통 원칙: 비교 실험은 같은 prompt, negative, seed, 해상도, sampler, scheduler, steps, CFG에서 **한 번에 한 변수만** 바꿨습니다. 생성 이미지에는 전체 설정과 checkpoint/LoRA 해시를 PNG metadata와 `manifest.json`으로 함께 저장했습니다.

공통 베이스 모델: waiIllustrious SDXL v1.6

## ① 스타일 LoRA 탐색 (2026.05 ~ 06)

| 버전 | 이미지-캡션 쌍 | 비고 |
|---|---:|---|
| clean v2 | 8,209 | 노이즈·효과선 필터 후 |

초기 문서에는 8,209, 8,219, 8,514 등 서로 다른 수가 적혀 있었습니다. 정제 단계와 캡션 버전 차이 때문이라, 실험 전에는 항상 실제 쌍 수를 다시 세고 학습된 가중치의 metadata와 대조했습니다 (`pipeline/audit_lora_metadata.py`).

### 모델 계보

| 모델 | 데이터 | 주요 설정 | 관찰 |
|---|---:|---|---|
| LoCon v2 (WD14 캡션) | 약 8,514 | dim 32/16, conv 8, 5 epoch, `keep_tokens=4` | 클로즈업·액션에서 안정적. 후속 모델보다 선호된 경우가 많음 |
| LoCon v3/v4 (EVA02 캡션) | 8,209 | conv 16, 최대 8 epoch, `keep_tokens=3` | 태그는 세밀해졌지만 구도·외형 안정성이 기대보다 낮음 |

| DoRA | 동일 | `dora_wd`, Tucker, `train_norm`, 1280px | 가는 선·펜 질감 개선 |
| LoCon v5 | 6,634 | 1280px, dim 16/8, conv 16/8, Tucker, rank dropout 0.05, U-Net only | 레퍼런스 선화 변환(A 과제)에서 e2 사용 |

### 캡셔닝 원칙

- WD14, EVA02는 Danbooru 태그 분류기라 선 끝, 테이퍼링, 필압을 기술하지 못합니다.
- 분리 가능한 속성(내용·인물·구도)은 캡션으로 빼고, 언어로 표현하기 어려운 펜 질감은 스타일 트리거가 흡수하도록 했습니다.
- `keep_tokens`는 실제 캡션의 고정 접두 토큰 수와 반드시 맞춥니다.
- 색상 태그, 오탐 캐릭터 태그, 작품명 태그는 제거합니다.
- 해칭은 자동 점수만으로 라벨링하지 않고, 저수준 지표는 사람 검수 순서를 정하는 데만 씁니다.

## ② 정체성과 평가 체계 (2026.07)

> 이 절의 수치는 당시 모델 기준입니다: 통합 캐릭터 LoCon + 스타일 DoRA, DPM++ 2M Karras, 28 steps, CFG 5. 현재 Studio 모델로 다시 측정한 값이 아닙니다.

평가 방법 자체는 [평가 프로토콜](evaluation_protocol.md)에 있습니다.

### 캐릭터 데이터와 캡션 오염 감사

캐릭터 데이터는 각 컷에서 목표 외 인물을 사람이 지운 정체성 전용 데이터입니다. 정체성 학습에는 유리하지만 캐릭터 간 체격 비율, 상호작용 위치, 군중 속 상대 크기 정보는 잃습니다. 그래서 스타일·구도 학습용 다인물 원본과 섞지 않았습니다.

`training/data_cleaning/audit_caption_contamination.py`

| 캐릭터 | 캡션 | 성별·수염 모순 | 다인/solo-focus 위험 |
|---|---:|---:|---:|
| Char_G | 69 | 43.5% | 24.6% |
| Char_H | 49 | 20.4% | 20.4% |
| Char_E | 101 | 9.9% | 14.9% |
| Char_F | 89 | 7.9% | 9.0% |
| Char_D | 59 | 1.7% | 5.1% |
| Char_A | 110 | 0.9% | 1.8% |
| Char_B | 104 | 0.0% | 1.0% |
| Char_C | 76 | 0.0% | 2.6% |

8명 × 2포즈 탐색 표본에서 오염률과 생성 통과율의 상관은 관찰되지 않았습니다(Spearman ρ=0.00, p=1.0). 오염은 확인된 위험 요인이지만 실패 원인으로 단정하지 않았습니다.

**정제 전후 A/B 재학습 설계**

- A: 기존 데이터 / B: 사람 검수 정제 데이터. 네트워크·optimizer·seed는 동일
- 정제로 이미지 수가 줄어도 epoch이 아니라 **총 optimizer step**을 맞추고, 같은 step 체크포인트끼리 비교
- 평가: 8명 × 포즈 4종 × 표정 4종 × 시드 4개, 하위 캐릭터 개선 여부를 paired bootstrap 신뢰구간으로 보고

## ⑤ 캐릭터별 모델과 B/C컷 Studio (2026.10 ~ 11)

### 캐릭터별 LoCon 학습

8명을 각각 따로 학습했습니다. 아래 값은 각 가중치의 학습 metadata에서 확인했습니다.

| 캐릭터 | 학습 당시 이미지 | repeat | 반복 적용 샘플 | 채택 epoch | 저장 step |
|---|---:|---:|---:|---:|---:|
| Char_A | 147 | 5 | 735 | 3 / 5 | 591 |
| Char_B | 128 | 6 | 768 | 3 / 5 | 603 |
| Char_E | 124 | 6 | 744 | 3 / 5 | 579 |
| Char_F | 106 | 7 | 742 | 3 / 5 | 585 |
| Char_C | 89 | 8 | 712 | 3 / 5 | 534 |
| Char_D | 77 | 10 | 770 | 3 / 3 | 603 |
| Char_G | 77 | 10 | 770 | 3 / 5 | 600 |
| Char_H | 58 | 13 | 754 | 3 / 5 | 597 |
| **합계** | **806** | | **5,995** | | |

- 데이터가 적은 캐릭터일수록 repeat를 높여 epoch당 노출을 맞췄습니다.
- 5,995는 optimizer step이 아니라 repeat를 적용한 샘플 노출 수입니다. 버킷 때문에 실제 배치 수는 단순히 batch size로 나눈 값과 다릅니다.
- 7명은 5 epoch 학습 중 e3을, Char_D는 3 epoch 학습의 최종본을 골랐습니다. e3이 모든 캐릭터에서 최적이라는 증명은 아닙니다.
- 공통 설정: LoCon dim 32/alpha 16, conv 16/8, Tucker, `train_norm`, 1024px 버킷(512~2048), batch 4, AdamW8bit, LR 1e-4, text encoder LR 5e-5, cosine, warmup 23, bf16, min SNR γ 5, `keep_tokens=4`, seed 42, augmentation 없음.

**데이터 버전 주의:** 현재 정제 폴더는 792쌍으로, Char_A가 학습 당시 147장에서 133장으로 줄어 있습니다. 빠진 14장의 이력은 확인하지 못했습니다. 현재 폴더로 다시 학습하면 같은 학습이 아니므로, 재학습 전에 데이터 파일 목록과 해시를 고정해야 합니다.

### 통합 모델과의 비교

8명을 함께 학습하고 캐릭터별 트리거로 구분하는 통합 LoCon(e8, 반복 적용 1,943샘플)과 비교했습니다. 추론 설정을 모두 맞추고 LoRA 식별자만 바꿨으며, 제작 쪽 정성 평가에서 개별 모델이 선택됐습니다.

두 모델의 학습 데이터가 완전히 같지 않아서, 이 결과는 "모델을 나누면 좋아진다"는 학습 ablation이 아니라 **추론 조건을 통제한 모델 비교**입니다. 통계적 우월성은 검증하지 않았습니다.

### 생성 설정

| 항목 | 값 |
|---|---|
| 방식 | Forge API txt2img, 896×1152 |
| sampler | Euler a / Automatic, 28 steps, CFG 5, CPU RNG |
| LoRA | 선택한 캐릭터 LoCon 1개, 강도 0.90. 별도 스타일 LoRA 없음 |

| 단계 | 설정 |

생성 응답에서 베이스와 LoRA 해시를 확인합니다. 프롬프트에 모델 이름이 적혀 있다는 사실만으로 적용됐다고 보지 않습니다.

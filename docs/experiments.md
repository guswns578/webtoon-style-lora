# 실험 기록

모든 비교 실험은 같은 prompt, negative, seed, 해상도, sampler, scheduler, steps, CFG에서 **한 번에 한 변수만** 바꿨습니다. 생성 이미지에는 전체 설정과 checkpoint/LoRA 해시를 PNG metadata와 `manifest.json`으로 함께 저장했습니다.

인물을 지운 데이터는 정체성 학습에 유리하지만 캐릭터 간 키·체격 비율, 상호작용 위치, 군중 속 상대 크기 정보를 잃습니다. 그래서 스타일·구도 학습용 다인물 원본과 섞지 않았습니다.

## 2. 모델 계보

### Style: WD14 기반 LoCon (v2)

- 약 8,514장, repeat 1, 5 epoch, `keep_tokens=4`, dim 32 / alpha 16, conv dim 8
- 클로즈업과 일부 액션 구도에서 안정적. 이후 EVA02 캡션 모델보다 선호된 경우가 많았습니다.

### Style: EVA02 Large v3 기반 LoCon (v3, v4)

- conv rank 16, 최대 8 epoch, `keep_tokens=3`
- 의상·포즈 태그는 세밀해졌지만, 내용 태그가 늘면서 스타일 토큰과 데이터 편향(남성 기사, 갑옷, 검)이 더 복잡하게 얽혔습니다.
- 결론: **캡션 정보량이 많다고 펜 질감이 좋아지지 않는다.**

### Full fine-tuning

- L40S에서 약 3 epoch
- 질감은 강해졌지만 선이 굵어지고 과적합. 2.6B 파라미터 전체 갱신은 데이터 편향에 비해 위험해서 기본안에서 제외했습니다.

### DoRA + 고해상도

- LyCORIS `dora_wd`, `use_tucker=True`, `train_norm=True`, 1280px
- 저랭크 LoRA보다 펜 질감과 가는 선이 좋아졌습니다.
- 스타일+캐릭터 통합 실험에서는 3 epoch 중 e2가 가장 좋았습니다.

### 스타일·캐릭터 분리 구조

```
<lora:style_locon_e3:0.65>, <lora:char_locon_e3:0.9>
DPM++ 2M Karras, 28 steps, CFG 5
```

이 값은 시작점이며 장면 유형별 grid로 다시 검증해야 합니다.

### 캐릭터별 solo LoCon

통합 캐릭터 모델 대신 캐릭터마다 별도 LoCon을 학습했습니다. 최종 Studio는 별도 스타일 LoRA 없이 캐릭터 solo 모델 0.90만 씁니다.

## 3. 캡셔닝 원칙

- WD14, EVA02는 Danbooru 태그 분류기라 작가 고유의 선 끝, 테이퍼링, 필압을 기술하지 못합니다.
- 분리 가능한 속성(내용·인물·구도)은 캡션으로 빼고, 언어로 표현하기 어려운 펜 질감은 스타일 트리거가 흡수하도록 했습니다.
- `keep_tokens`는 실제 캡션의 고정 접두 토큰 수와 반드시 맞춥니다.
- 색상 태그, 오탐 캐릭터 태그, 작품명 태그는 제거합니다.
- 해칭은 자동 점수만으로 라벨링하지 않고, 저수준 지표는 사람 검수 순서를 정하는 데만 씁니다.

| Char_H | 49 | 20.4% | 20.4% |
| Char_E | 101 | 9.9% | 14.9% |

8명 × 2포즈 탐색 표본에서는 오염률과 생성 통과율의 상관이 관찰되지 않았습니다(Spearman ρ=0.00, p=1.0, `pipeline/correlate_caption_audit_benchmark.py`). 오염은 확인된 위험 요인이지만 실패 원인으로 단정하지 않았습니다.

### 정제 전후 A/B 재학습 설계

| Run | 데이터 | 네트워크 |
|---|---|---|
| A | 기존 캐릭터 데이터 | 기존 LoCon 설정 |
| B | 사람 검수 정제 데이터 | A와 완전히 동일 |

- 정제로 이미지 수가 줄어도 epoch이 아니라 **총 optimizer step**을 맞추고, 같은 step 체크포인트끼리 비교합니다.
- 평가: 8명 × 포즈 4종 × 표정 4종 × 시드 4개
- 판정: 평균뿐 아니라 하위 캐릭터(Char_G, Char_E, Char_F)가 개선돼야 하며, paired bootstrap 신뢰구간으로 보고합니다.

## 5. 캐릭터 × 포즈 벤치마크

`pipeline/character_pose_benchmark.py`, 8명 × 2포즈 × 2시드

| crossed (팔짱) | 100% | 87.5% | 0.0824 |

### 입력 포즈 품질

| 포즈 | 검출 관절 | 사용 가능 |
|---|---:|---|
| punch | 16 | 예 |
| crossed | 18 | 예 |

kneel 실험은 목표 스켈레톤이 사실상 검출되지 않아 **실험 자체가 무효**였습니다. 이후 8관절 미만 입력은 생성 전에 차단합니다.

### 표적 복구

| 캐릭터 / 포즈 | 개입 | 정체성 | 포즈 | 판정 |
|---|---|---|---:|---|
| Char_D / crossed | 캐릭터 LoCon 1.10 | CCIP 0.0417, Top-1 | 0.8004 | 복구 |
| Char_E / punch | 캐릭터 LoCon 1.15 | CCIP 0.0724, Top-1 | 0.4225 | 정체성만 복구, 검수 |
| Char_G / punch | LoCon 1.10 + 캐릭터 negative | 0.0785, Char_D로 오인 | 0.4169 | 실패 |
| Char_G / punch | 832×1216 + ControlNet 1.10 | 0.0800, Char_B로 오인 | 검출 불가 | 실패 |
| Char_D / crossed | LoCon 1.10 + 얼굴 인페인팅 0.52 | CCIP 0.0429, Top-1 | 0.7367 | 둘 다 통과 |

- 캐릭터 가중치는 캐릭터별 레버이지 전역 해결책이 아닙니다.
- Char_G punch는 가려진 어려운 포즈와 정체성 혼동이 겹친 사례라, 가중치 스윕을 더 하지 않고 데이터 정제 A/B로 넘겼습니다.

## 6. 표정 벤치마크

8명 × 4표정, 대표 시드

| 표정 | 캐릭터 Top-1 | 운영 임계값 통과 | 평균 목표 거리 |
|---|---:|---:|---:|
| angry | 8/8 | 8/8 | 0.0550 |
| smile | 8/8 | 8/8 | 0.0502 |
| neutral | 7/8 | 7/8 | 0.0459 |
| sad | 7/8 | 7/8 | 0.0472 |

neutral, sad의 실패는 모두 Char_D가 Char_B로 분류된 경우였습니다. 수염·성인 남성 얼굴 축이 두 캐릭터를 혼동시킨다는 기존 관찰과 일치합니다.

4시드 견고성에서는, 단일 시드 기준으로 고친 프롬프트(`seed_fix`)가 Char_D angry, Char_A angry 모두 50%로 오히려 나빠졌습니다. **단일 시드에서 좋아 보이는 수정이 시드 견고성을 보장하지 않는다**는 반례입니다.

## 7. 군중 베이스라인

`pipeline/crowd_ab_baseline.py`: style LoRA 하나로 일반 병사 군중이 안정되는지 확인

| 고정 조건 | 값 |
|---|---|
| seed / size | 43 / 1216×832 |
| sampler | DPM++ 2M Karras, 28 steps, CFG 5 |
| ControlNet | 사용 안 함 |
| 변경 변수 | style LoRA weight 0.00 vs 0.65 |

| 지표 | 0.00 | 0.65 |
|---|---:|---:|
| 평균 명도 | 150.52 | 117.51 |
| 진한 잉크 비율 (<80) | 12.13% | 18.72% |
| 흰 여백 비율 (>245) | 0.00% | 0.12% |
| 에지 밀도 | 22.22% | 16.77% |
| 평균 채도 | 1.31 | 1.16 |

- 두 조건 모두 지정한 6명을 지키지 못하고 수십 명으로 늘어났습니다.
- style 적용 후 검은 면이 오히려 늘었고, 흰 여백·가는 선은 둘 다 실패했습니다.
- 재실행 후 RGB 픽셀 SHA256이 완전히 같아 재현성을 확인했습니다.
- style 모델 학습 태그에서 `6+boys` 212, `soldier` 102로 군중 분포가 부족했습니다.

결론: weight 하나로는 인원수·배치·여백을 동시에 통제할 수 없습니다. 다음 실험은 weight를 고정하고 `ControlNet 없음` vs `6인 공간 조건`만 비교하는 것입니다. 시드 하나의 결과라 일반화하지 않았습니다.

## 8. Studio 검증

- 환경: Windows, Python 3.11, Gradio 6.20, Forge Neo 2.27, PyTorch 2.11 + cu130, RTX 5070 12GB
- 8명 전체를 한 번에 등록 → 8개 작업 모두 검수 대기로 완료, B/C컷 16장 생성
- 생성 기록에서 모델 이름과 적용 해시를 확인
- 가중치 10개 크기·SHA256 검증 통과 (합계 약 11.3GB)
- 자동 테스트 12개 (5개 영역): 큐 취소·복구, B/C 크기·마스크·수정 이력·ZIP, 수동 마스크 복구, 얼굴 검출 실패 안내, 외부 서버 주소 거부
- 미검증: 다른 PC의 최초 설치, 다른 GPU·Forge 버전에서의 동일 결과
